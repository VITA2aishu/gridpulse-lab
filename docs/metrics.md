# Metrics reference

`GET /metrics` returns a Prometheus text exposition
(`text/plain; version=0.0.4; charset=utf-8`) rendered by the dependency-free
exporter in `src/gridpulse/metrics.py`. No Prometheus client library is
required. Every series describes the fictional fleet: all assets, regions and
values are generated by the simulator.

For scrape setup and a Grafana walkthrough see the
[observability quick start](observability.md). For the JSON endpoints see the
[API reference](api.md); for example queries see the
[PromQL examples](promql.md).

## Metric list

All metrics are gauges. Each scrape reflects the simulator snapshot taken at
request time, so samples carry no explicit timestamp.

| Metric | Type | Labels | Meaning |
|---|---|---|---|
| `gridpulse_active_alarms` | gauge | — | Number of active derived alarms across the fleet |
| `gridpulse_active_incidents` | gauge | — | Number of active synthetic incidents |
| `gridpulse_telemetry_age_seconds` | gauge | `asset_id`, `region` | Age in seconds of the newest observation for the asset |
| `gridpulse_processing_lag_seconds` | gauge | `asset_id`, `region` | Delay in seconds between the newest observation and application processing |
| `gridpulse_quality_points` | gauge | `quality` | Number of telemetry points in each quality state, counted across the fleet |
| `gridpulse_progression_state` | gauge | `asset_id`, `status` | Progression state as a one-hot gauge; `1` marks the current state |
| `gridpulse_health_score` | gauge | `asset_id`, `region` | Combined telemetry-health score from 0 to 100 |
| `gridpulse_health_state` | gauge | `asset_id`, `status` | Combined health state as a one-hot gauge; `1` marks the current state |

Label values are escaped for backslash, double quote and newline as required by
the exposition format.

### Label values

| Label | Values | Produced by |
|---|---|---|
| `asset_id` | `aurora-1`, `bluebonnet-1`, `canyon-1` on the default fictional fleet | asset configuration |
| `region` | `North`, `Central`, `West` on the default fictional fleet | asset configuration |
| `quality` | `good`, `stale`, `bad`, `missing` | quality engine (see [API reference](api.md)) |
| `status` on `gridpulse_progression_state` | `progressing`, `unchanged`, `frozen` | progression engine |
| `status` on `gridpulse_health_state` | `healthy`, `degraded`, `stale`, `failed` | health engine |

The one-hot gauges emit one series per asset per possible state. Exactly one
state series per asset reports `1`; the others report `0`. This keeps PromQL
readable, for example `gridpulse_progression_state{status="frozen"} == 1` or
`sum by (status) (gridpulse_health_state)`.

## Freshness, progression and processing lag

Three timing signals appear in the exposition. They look similar but answer
different operational questions:

- **Freshness** — `gridpulse_telemetry_age_seconds` compares the newest
  *observation* timestamp with the evaluation time. It asks: how old is the
  newest source data?
- **Progression** — `gridpulse_progression_state` tracks whether the newest
  observation timestamp keeps advancing between evaluations. It asks: is the
  stream still moving? Progression is based on timestamps, not values, so a
  reading that stays numerically constant still counts as progressing while
  fresh observations keep arriving. A stream that stops advancing first reads
  `unchanged`, then `frozen` once the freeze window elapses (10 seconds in the
  default lab configuration).
- **Processing lag** — `gridpulse_processing_lag_seconds` measures the delay
  between the newest observation and the application's processing pass. It
  asks: how much of the delay is on the application side rather than at the
  source?

The distinction matters because the signals can diverge:

- a frozen feed shows a growing telemetry age **and**
  `progression_state{status="frozen"} == 1`;
- a source emitting old or backfilled timestamps can show a large telemetry age
  while progression stays `progressing` — the stream advances, but the data is
  not fresh;
- an application-side delay would raise processing lag without necessarily
  meaning the source went stale.

In the current simulator both time comparisons are evaluated against the same
snapshot timestamp, so the exported freshness and lag values coincide. They are
exported separately so an application-side delay can be alerted on
independently and is never silently folded into a source-freshness signal.

## Low-cardinality label design

The exporter deliberately keeps the label space small:

- Only four label keys are used: `asset_id`, `region`, `status` and `quality`.
- `asset_id` and `region` are bounded by the small fictional fleet — three
  assets by default.
- `status` and `quality` take values from fixed enumerations, so their series
  counts are predictable. With the default fleet the exporter emits 9
  `gridpulse_progression_state` series (3 assets × 3 states), 12
  `gridpulse_health_state` series (3 assets × 4 states) and 4
  `gridpulse_quality_points` series.
- Detail that would grow cardinality unboundedly — telemetry point names,
  observation timestamps, incident kinds and alarm identifiers — is
  intentionally kept out of metric labels. It remains available through
  `GET /api/v1/telemetry` and `GET /api/v1/incidents`.

This keeps scraping, storage and dashboards cheap while preserving the labels
needed to filter by asset and state.

## Sample exposition

Healthy default fleet:

```text
# HELP gridpulse_active_alarms Number of active derived alarms.
# TYPE gridpulse_active_alarms gauge
gridpulse_active_alarms 0
# HELP gridpulse_active_incidents Number of active synthetic incidents.
# TYPE gridpulse_active_incidents gauge
gridpulse_active_incidents 0
# HELP gridpulse_telemetry_age_seconds Age of the newest observation for an asset.
# TYPE gridpulse_telemetry_age_seconds gauge
gridpulse_telemetry_age_seconds{asset_id="aurora-1",region="North"} 0.0
gridpulse_telemetry_age_seconds{asset_id="bluebonnet-1",region="Central"} 0.0
gridpulse_telemetry_age_seconds{asset_id="canyon-1",region="West"} 0.0
# HELP gridpulse_processing_lag_seconds Delay from newest observation to application processing.
# TYPE gridpulse_processing_lag_seconds gauge
gridpulse_processing_lag_seconds{asset_id="aurora-1",region="North"} 0.0
gridpulse_processing_lag_seconds{asset_id="bluebonnet-1",region="Central"} 0.0
gridpulse_processing_lag_seconds{asset_id="canyon-1",region="West"} 0.0
# HELP gridpulse_quality_points Number of telemetry points by quality state.
# TYPE gridpulse_quality_points gauge
gridpulse_quality_points{quality="good"} 18
gridpulse_quality_points{quality="stale"} 0
gridpulse_quality_points{quality="bad"} 0
gridpulse_quality_points{quality="missing"} 0
# HELP gridpulse_progression_state Asset progression state encoded as a one-hot gauge.
# TYPE gridpulse_progression_state gauge
gridpulse_progression_state{asset_id="aurora-1",status="progressing"} 1
gridpulse_progression_state{asset_id="aurora-1",status="unchanged"} 0
gridpulse_progression_state{asset_id="aurora-1",status="frozen"} 0
gridpulse_progression_state{asset_id="bluebonnet-1",status="progressing"} 1
gridpulse_progression_state{asset_id="bluebonnet-1",status="unchanged"} 0
gridpulse_progression_state{asset_id="bluebonnet-1",status="frozen"} 0
gridpulse_progression_state{asset_id="canyon-1",status="progressing"} 1
gridpulse_progression_state{asset_id="canyon-1",status="unchanged"} 0
gridpulse_progression_state{asset_id="canyon-1",status="frozen"} 0
# HELP gridpulse_health_score Combined telemetry-health score from 0 to 100.
# TYPE gridpulse_health_score gauge
# HELP gridpulse_health_state Combined asset health state encoded as a one-hot gauge.
# TYPE gridpulse_health_state gauge
gridpulse_health_score{asset_id="aurora-1",region="North"} 100

gridpulse_health_state{asset_id="aurora-1",status="degraded"} 0
gridpulse_health_state{asset_id="aurora-1",status="stale"} 0
gridpulse_health_state{asset_id="aurora-1",status="failed"} 0
gridpulse_health_score{asset_id="bluebonnet-1",region="Central"} 100
gridpulse_health_state{asset_id="bluebonnet-1",status="healthy"} 1
gridpulse_health_state{asset_id="bluebonnet-1",status="degraded"} 0
```
